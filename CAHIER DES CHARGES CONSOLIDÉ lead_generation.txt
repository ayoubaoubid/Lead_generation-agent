# CAHIER DES CHARGES CONSOLIDÉ

## Plateforme multiclient de Lead Generation & Sales Automation pilotée par l’IA

---

# Correction de périmètre — modèle commercial

La plateforme n'est pas un SaaS public en libre-service. L'agence négocie et signe ses contrats directement avec ses clients hors plateforme, puis un administrateur autorisé crée manuellement le client, son workspace, ses utilisateurs, ses rôles, ses intégrations et ses quotas.

Sont définitivement hors périmètre : Stripe, checkout, paiement en ligne, facturation automatique, plans tarifaires, abonnements SaaS, essais gratuits, coupons, taxes, cartes bancaires, factures client automatiques, portails de billing, webhooks de paiement, `PaymentProvider`, `BillingProvider` et toute table de paiement.

Les crédits, coûts, quotas et limites conservés concernent uniquement la consommation technique des fournisseurs externes. Ils ne constituent pas un système de paiement ou de facturation client.

# 1. Présentation du projet

## 1.1 Nom provisoire

**AI Lead Generation & Sales Operations Platform**

## 1.2 Vision

Construire une plateforme professionnelle permettant à une agence de lead generation ou d’automatisation commerciale de gérer plusieurs clients simultanément depuis un seul système.

La plateforme devra automatiser le processus complet :

```text
Onboarding du client
→ compréhension de son marché
→ construction de son offre
→ définition de son ICP
→ définition des buyer personas
→ recherche des entreprises
→ recherche des décideurs
→ enrichissement
→ vérification
→ qualification
→ segmentation
→ création de campagne
→ personnalisation des messages
→ validation humaine
→ envoi
→ relances
→ analyse des réponses
→ prise de rendez-vous
→ gestion du pipeline
→ closing
→ reporting
→ optimisation continue
```

La plateforme ne doit pas être uniquement :

* un scraper ;
* un outil d’emailing ;
* un CRM ;
* un ensemble de workflows Trigger.dev ;
* une interface d’agents IA.

Elle doit devenir un véritable système de **Lead Operations, Sales Operations et Revenue Operations pour agences B2B**.

# 3. Architecture multitenant

## 3.1 Hiérarchie métier

```text
Plateforme
└── Agence
    ├── Membres de l’agence
    ├── Paramètres globaux
    ├── Bibliothèque de templates
    ├── Intégrations partagées
    └── Clients
        ├── Utilisateurs clients
        ├── Offres
        ├── ICP
        ├── Personas
        ├── Entreprises
        ├── Contacts
        ├── Campagnes
        ├── Boîtes email
        ├── Calendriers
        ├── Réponses
        ├── Rendez-vous
        ├── Pipeline
        └── Rapports
```

## 3.2 Isolation des données

Toutes les entités métier doivent être liées à :

```text
agency_id
client_id
```

Certaines entités globales peuvent uniquement contenir :

```text
agency_id
```

Exemples :

* utilisateurs internes ;
* budgets, quotas et coûts techniques de l’agence ;
* paramètres globaux ;
* bibliothèque de templates partagés ;
* quotas ;
* coûts globaux.

## 3.3 Règle fondamentale

Aucune requête frontend, backend, tâche Trigger.dev ou agent IA ne doit faire confiance directement à un `client_id` transmis par l’utilisateur.

Chaque action doit vérifier :

```text
l’utilisateur appartient à l’agence ;
le client appartient à l’agence ;
l’utilisateur possède le rôle nécessaire ;
la ressource appartient au client ;
l’intégration appartient au même client ;
la campagne appartient au même tenant.
```

# 7. Gestion des dix skills commerciaux

Les dix skills sont conservés, mais ils doivent être adaptés au fonctionnement réel de la plateforme.

Le catalogue indique notamment que Diagnose sert à distinguer un problème de ciblage, d’offre, de message ou de canal, tandis que Mom Test sert à identifier des besoins réels à partir des comportements passés.

## 7.1 Skill Diagnose

### À conserver

* analyse des problèmes commerciaux ;
* distinction ciblage, offre, message, canal et prix ;
* recommandation du skill suivant ;
* proposition d’une action.

### À modifier

Ajouter les causes techniques :

* taux de rebond élevé ;
* domaine mal configuré ;
* email invalide ;
* mauvaise réputation ;
* mauvais horaire ;
* séquence trop agressive ;
* données incomplètes ;
* intégration déconnectée ;
* queue Trigger.dev bloquée ;
* problème de qualification ;
* faible qualité de personnalisation.

### Sortie obligatoire

```json
{
  "diagnosis": "",
  "probableCauses": [],
  "confidence": 0,
  "recommendedSkill": "",
  "recommendedActions": [],
  "requiredEvidence": []
}
```

### Agent utilisateur

```text
Analytics Agent
Campaign Optimization Agent
Orchestrator Agent
```

# 14. RLS Supabase

RLS doit être activé sur toutes les tables sensibles.

Règles :

```text
Un membre de l’agence voit les ressources de son agence.

Un utilisateur client voit uniquement les ressources des clients auxquels il est affecté.

Un reviewer peut approuver mais pas administrer.

Un viewer peut lire mais pas modifier.

Un agent backend utilisant une clé de service doit refaire les contrôles de tenant dans le code.
```

Tests obligatoires :

* Agence A ne voit pas Agence B ;
* Client A ne voit pas Client B ;
* reviewer ne peut pas supprimer ;
* viewer ne peut pas envoyer ;
* utilisateur désactivé perd immédiatement l’accès ;
* tâche Trigger.dev ne peut pas traiter une ressource d’un autre tenant.

```text
L’agence crée plusieurs clients

                    ↓

                    ↓
La plateforme crée l’ICP et les personas
                    ↓
Elle recherche et enrichit les prospects
                    ↓
Elle vérifie et qualifie les données
                    ↓
Elle segmente les leads
                    ↓

                    ↓

                    ↓
Elle valide les actions sensibles
                    ↓

                    ↓

                    ↓

                    ↓

                    ↓

                    ↓
```

Le résultat final est une plateforme multitenant complète permettant à une agence B2B de gérer l’acquisition, la prospection et la vente de plusieurs clients depuis une seule interface, avec une orchestration durable, une intelligence commerciale structurée et une isolation stricte des données.
