# Cahier des charges — Plateforme intelligente de Lead Generation & Sales Automation

> Correction de périmètre définitive : la plateforme est opérée par une agence et ne contient aucun paiement en ligne, abonnement SaaS, plan tarifaire, checkout, billing ou Stripe. Les contrats sont conclus hors plateforme et les espaces clients sont créés manuellement par un administrateur autorisé. Les crédits et quotas concernent uniquement les fournisseurs techniques.

## 1. Présentation générale du projet

### 1.1 Nom provisoire

**AI Lead Generation & Sales Automation Platform**

### 1.2 Vision

Construire une plateforme capable d’automatiser une grande partie du travail réalisé par une agence de lead generation, une équipe SDR ou une équipe commerciale B2B.

Le système devra permettre de :

* définir une cible commerciale ;
* rechercher des entreprises ;
* identifier les décideurs ;
* enrichir les données ;
* vérifier la qualité des coordonnées ;
* qualifier les prospects ;
* créer des campagnes multicanales ;
* personnaliser les messages avec l’IA ;
* envoyer les campagnes ;
* effectuer les relances ;
* analyser les réponses ;
* gérer les rendez-vous ;
* suivre les opportunités commerciales ;
* mesurer les performances ;
* synchroniser les données avec un CRM.

La plateforme ne doit pas être un simple outil d’envoi d’emails. Elle doit couvrir le processus commercial complet :

```text
Stratégie
→ Recherche
→ Enrichissement
→ Qualification
→ Prospection
→ Conversation
→ Rendez-vous
→ Opportunité
→ Vente
→ Analyse
→ Optimisation
```

La plateforme doit permettre de :

* faciliter la prise de rendez-vous ;

* sécurisé ;
* multiclient ;
* maintenable ;
* extensible ;
* observable ;
* testable ;

* compatible avec plusieurs fournisseurs d’IA ;

* capable de gérer les erreurs et les reprises ;

## 4.8 Phase 8 — Qualification et scoring

La qualification combine des règles déterministes et une analyse IA.

### Types de scoring

#### Fit Score

Mesure la compatibilité avec l’ICP.

Exemples :

* secteur compatible ;
* pays ciblé ;
* taille adaptée ;
* activité compatible ;
* technologie pertinente ;
* budget potentiel ;
* persona disponible.

#### Intent Score

Mesure les signaux d’intérêt ou de besoin.

Exemples :

* recrutement récent ;
* nouvelle implantation ;
* croissance ;
* changement de direction ;
* projet annoncé ;
* téléchargement d’un contenu ;
* visite d’une page ;
* réponse précédente ;
* interaction avec une campagne.

#### Data Quality Score

Mesure la qualité des données.

Exemples :

* domaine vérifié ;
* décideur identifié ;
* email valide ;
* téléphone disponible ;
* sources fiables ;
* données récentes.

#### Engagement Score

Mesure les interactions avec la prospection.

Exemples :

* email délivré ;
* clic ;
* réponse ;
* rendez-vous ;
* demande d’information ;
* interaction antérieure.

### Exemple de score global

```text
Score global =
40 % Fit Score
+ 25 % Intent Score
+ 20 % Data Quality Score
+ 15 % Engagement Score
```

### Classification

```text
90–100 : priorité critique
75–89  : très qualifié
60–74  : qualifié
40–59  : à enrichir
0–39   : non qualifié
```

### Sorties du moteur

* score total ;
* sous-scores ;
* statut ;
* raisons ;
* critères satisfaits ;
* critères manquants ;
* risques ;
* prochaine action recommandée ;
* confiance du modèle ;
* date du calcul ;
* version du modèle de scoring.

## 4.14 Phase 14 — Relances automatiques

Une séquence peut contenir plusieurs étapes.

### Exemple

```text
Jour 0  : premier email
Jour 3  : relance 1
Jour 7  : relance 2
Jour 14 : relance finale
```

### Règles d’arrêt

La séquence doit s’arrêter si :

* le prospect répond ;
* le prospect se désabonne ;
* l’email rebondit ;
* un rendez-vous est réservé ;
* le prospect est blacklisté ;
* le contact change d’entreprise ;
* l’utilisateur arrête manuellement la séquence ;
* la campagne atteint une date limite ;
* une règle de conformité bloque l’envoi.

### Adaptation par IA

L’IA peut proposer une relance différente selon :

* le message précédent ;
* les informations disponibles ;
* le niveau d’engagement ;
* le rôle du prospect ;
* l’objectif de la campagne.

# 15. Conformité et protection des données

La plateforme doit intégrer la conformité dès sa conception.

Le RGPD protège les personnes physiques lorsque leurs données personnelles sont traitées. Les données purement liées à une personne morale ne sont pas traitées de la même manière, mais les coordonnées professionnelles nominatives d’un salarié restent associées à une personne physique.

## Exigences

* définir la finalité de chaque traitement ;
* documenter la base juridique ;
* limiter les données collectées ;
* informer les personnes concernées ;
* enregistrer les sources ;
* permettre l’opposition ;
* permettre la suppression lorsque cela s’applique ;
* limiter les durées de conservation ;
* sécuriser les données ;
* contrôler les sous-traitants ;
* gérer les violations de données ;
* conserver un registre des traitements ;
* gérer les demandes d’exercice des droits.

## Prospection

Les règles ne sont pas identiques pour la prospection B2B et B2C. La configuration du système doit donc distinguer clairement le type de destinataire, le canal, le pays et la base juridique avant tout envoi. La CNIL rappelle notamment que la prospection électronique B2C nécessite généralement un consentement préalable, tandis que d’autres situations peuvent relever d’un mécanisme d’opposition, sous réserve de respecter les conditions applicables.

## Liste d’exclusion

Le système doit conserver une liste d’exclusion permettant de ne pas recontacter une personne ayant exercé son droit d’opposition. La CNIL recommande de conserver les informations nécessaires à la prise en compte de cette opposition pendant au moins trois ans, sans les réutiliser à d’autres fins.

## Conservation

Les durées doivent être paramétrables selon le type de données et la finalité. Pour les prospects, la CNIL rappelle notamment une durée pouvant aller jusqu’à trois ans à compter de la collecte ou du dernier contact réellement initié par le prospect ; la simple ouverture d’un email ne constitue pas ce contact.

## Fonctions techniques obligatoires

* centre de préférences ;
* lien ou mécanisme d’opposition ;
* suppression globale ;
* export des données ;
* liste de suppression ;
* journal des consentements ou bases juridiques ;
* preuve de la source ;
* politique de rétention ;
* purge automatique ;
* anonymisation ;
* isolation par client ;
* chiffrement ;
* audit.

Une validation juridique adaptée aux pays ciblés reste nécessaire avant une mise en production commerciale.

# 27. Principes d’architecture essentiels

## Principe 1

```text
L’IA comprend, extrait, classe et recommande.
Le code déterministe contrôle, valide et exécute.
```

## Principe 2

Aucun agent ne doit pouvoir envoyer, supprimer ou modifier massivement des données sans permissions et limites.

## Principe 3

Chaque information externe doit conserver sa source.

## Principe 4

Chaque décision IA importante doit être traçable.

## Principe 5

Les workflows doivent être idempotents : une tâche relancée ne doit pas provoquer un double envoi.

## Principe 6

Les fournisseurs externes doivent pouvoir être remplacés.

## Principe 7

La conformité, la sécurité et la délivrabilité ne doivent pas être ajoutées à la fin. Elles font partie du produit dès la première version.

# 28. Résultat final attendu

À la fin du projet, la plateforme devra pouvoir exécuter le processus suivant :

```text
Le client configure son entreprise et son offre
                    ↓
Il définit son ICP et ses personas
                    ↓
Le système trouve ou importe des entreprises
                    ↓
Il identifie les décideurs
                    ↓
Il enrichit et vérifie les données
                    ↓
Il qualifie et segmente les prospects
                    ↓
Il crée une campagne multicanale
                    ↓
L’IA génère les messages personnalisés
                    ↓
Un humain valide les messages importants
                    ↓
Le système envoie et relance
                    ↓
Il reçoit et analyse les réponses
                    ↓
Il arrête les séquences inutiles
                    ↓
Il propose ou réserve un rendez-vous
                    ↓
Il crée une opportunité commerciale
                    ↓
Il suit le pipeline jusqu’à la vente
                    ↓
Il mesure les résultats et les coûts
                    ↓
Il recommande des optimisations
```

La plateforme devient ainsi un véritable système de **Revenue Operations**, et non uniquement un logiciel de collecte de leads ou d’envoi d’emails.
